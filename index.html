04 / THE LOOP

หนึ่งรอบที่ดี
มีจุดหยุดเสมอ

ให้ agent ทำงานเป็นช่วงสั้น ๆ ที่อ่าน diff และผลตรวจสอบได้ ไม่ปล่อยให้ “แก้ต่อไปเรื่อย ๆ” กลายเป็น process

01

Inspect

อ่าน repository, สถานะ branch, tests และข้อจำกัดก่อนเสนอวิธีแก้

status / diff
02

Plan

เขียน acceptance criteria, failure paths และขอบเขตไฟล์ที่ต้องแตะ

plan / scope
03

Edit

แก้ทีละ behavior ให้ diff เล็กพอที่คนอื่นจะ review ได้ในครั้งเดียว

edit / commit
04

Verify

รัน test, lint, build หรือ reproduction ที่พิสูจน์ behavior ใหม่จริง

test / diff
05

Handoff

สรุปสิ่งที่เปลี่ยน หลักฐานที่ตรวจ และความเสี่ยงก่อน PR หรือ deploy

PR / review

05 / GUARDRAILS

ขอบเขตที่ชัด
ทำให้ agent เก่งขึ้น

ความเร็วที่ไม่มี approval boundary คือหนี้สิน ให้สิทธิ์ตามผลกระทบ ไม่ใช่ตามความมั่นใจของโมเดล

!

หยุดและขออนุมัติ

  • เงิน ข้อมูลส่วนตัว และสิทธิ์ deploy
  • push, merge, rebase หรือแก้ประวัติ
  • ส่งข้อความหรือเปลี่ยนระบบภายนอก
✓

ทำต่อได้ใน scope

  • อ่านไฟล์และค้นหา dependency
  • แก้โค้ดใน branch ที่แยกแล้ว
  • รัน test / lint / build ที่ไม่ทำลายข้อมูล
⌁

ถ้าไม่แน่ใจ

  • บันทึกสถานะก่อนทำ recovery
  • สรุปทางเลือกและ trade-off
  • หยุดเมื่อเจอ conflict ไม่เลือกฝั่งเงียบ ๆ

06 / POCKET CARD

คำสั่งที่ควร
อยู่ข้างมือ

เก็บส่วนนี้ไว้ใกล้ terminal สำหรับ session แรกหรือเวลาต้องกู้สถานะอย่างมีสติ

git restore pathทิ้งการแก้ของไฟล์นั้น
git restore --staged pathเอาไฟล์ออกจาก staging
git merge --abortยกเลิก merge ที่ conflict
git reset --soft HEAD~1แก้ commit local โดยเก็บไฟล์
git revert <commit>หักล้าง commit ที่ push แล้ว
git reset --harddestructive — ขอ approval ก่อน
